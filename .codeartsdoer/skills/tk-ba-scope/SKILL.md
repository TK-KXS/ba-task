# TK BA — Scope Definition

Always include:

- **Project objective** – 1–3 measurable outcomes (SMART).
- **In scope** – numbered capabilities, grouped by module.
- **Out of scope** – numbered, each with a reason ("Phase 2", "Customer responsibility", "Not requested").
  Anything the customer called "maybe", "phase 2", "nice to have" goes here explicitly.
- **Phasing** – Pilot / Phase 1 / Phase 2 table with timeline.
- **Stakeholders** – RACI table (Responsible, Accountable, Consulted, Informed).
- **Assumptions** – `AS-xx`, each with impact if wrong.
- **Dependencies** – external systems, customer deliverables (policy document, API access, test data).
- **Constraints** – budget, deadline, team size, technology, regulation.

Priority uses **MoSCoW**: Must / Should / Could / Won't (this time).
